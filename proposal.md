# Evidence-Grounded Browser Playtesting of AI-Generated Games

A contributor-owned, public evaluation-method research task motivated by AI Game
Bench. The runnable v0.3 source, frozen games, unchanged reference and matched
16-action validation are available. This revision does not claim revised
maintainer acceptance, independent reproduction or an Agent trajectory.

| Evaluation | Fixed evaluation protocol | Two game implementations × three fixed variants (original mechanics, removal-disabled, clear-reward-disabled) × 16 setup seeds 100–115 = 96 full cases. Development has eight disjoint seeds 10–17 = 48 cases. Starting wells cover width 1–8 and depth 2–5; public fixed PRNG/clock. Each case receives a fresh context and policy process, 16 actions and 30 wall seconds. Keys advance 32 simulated ms; waits permit 16–2000 ms. Restart/repeat/wait consume actions. No retries, replacement or resampling. Judge deadline 900 s. Candidate and baseline use the same cases, observations, budget and scorer; normal evaluation is candidate-only, not a live paired baseline. Python/syntax/illegal-action failures, process crashes, malformed reports, deadlines and incomplete evaluation are unscored, as are infrastructure failures; none become game defects. |
| Evaluation | Evaluation mode and input | Direct execution/evaluation of the final policy artifact; no evaluation-time retraining or candidate-production loop in Judge. The policy receives only rendered 20×10 board cell-center RGB samples, frame number, visible counters/overlay and remaining action budget. Optional board PNG observations show the same board and are equally available. No game JS state, source, creator/model ID, seed, variant or certificate is delivered through the policy API. |
| Evaluation | Reward or score definition | Maximize unitless balanced evidence-supported correct-decision rate in [0,1]: `0.5 × (correct positive / 96 + correct negative / 64)` for full evaluation. A judgment is correct only if its pass/fail label matches and its referenced adjacent before/after frames contain a task-owned certificate supporting that requirement. Unverified, incorrect and unsupported claims earn no credit. Score-on-clear is ineligible in removal-disabled cases, because its conditional event never occurs; hence 160 eligible judgments. Valid but wholly inaccurate reports may score zero. Candidate-invalid, timeout, infrastructure and incomplete outcomes have `score: null` and no finite reward. |
| Evaluation | Feedback visible to the agent | Aggregate score, eligible/class/correct counts, abstentions, unsupported decisions, total actions/time, policy digest, browser version, completeness/status and bounded validation reason. ## Public report context and review limitations

[Selected Codex and Claude Code findings](https://github.com/haot3x/OpenRSI-Game/blob/b9802fff1b384847ecfa4d1cbfd7d458a1ab7118/reports/README.md)
show why state-reaching matters: a historical evaluator left two Sol mechanics
unverified, while separate controlled QA demonstrated line clearing. Historical
claims remain unchanged and are not calibrated gold labels.
The selected Claude Code record used **MiniMax-M3**, not an Anthropic Claude
model. No other creation platform's results are included. The executable v0.3
has two Codex games; it does **not** claim a runnable Claude Code artifact or a
matched Codex/Claude model comparison.

[Validation and compatibility evidence](https://github.com/haot3x/OpenRSI-Game/blob/f65bd75867ac4463d0a0b17ab7717a774e377e0a/baselines/16-action-validation.json):
the official RSI-Harness HarborTaskCompiler at OpenRSI-Index commit
`dcfbc43b117b92d276837aa0d48f291d544fcf7a` successfully compiled the package;
the ordinary offline image and actual Judge script ran locally. No full paid
Codex/Claude research-agent Harness run was performed. Broader scientific
eligibility, small-corpus overfitting and future asset coverage require review.

## Disclosed protocol revision

The contributor authorized continued calibration to resolve baseline saturation.
The reference algorithm and its bytes remain unchanged. The interaction budget
is a Task-design change: 80-action full baseline 0.875; 40-action full calibration
0.8125, rejected; final 16-action full baseline 0.625. Development at 40/32/24
scored 0.6875 and at 16 scored 0.50. No cases were removed and no labels,
certificate rules or scoring changed. Selection used public development and
disclosed full calibration, not a secret holdout. The budget is fixed before
Agent optimization. Cross-budget score changes are not Agent improvement.
Local execution readiness remains separate from revised maintainer review,
a completed experiment trajectory and final inclusion.
